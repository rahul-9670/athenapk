### Two traps that cost real time, both verified

* **An unknown CLI key is SILENTLY INERT.** Parthenon accepts any `block/key=value`, prints
  "Parameter … will be added", and carries on. If the binary has no code reading it, you get a
  plausible run with the feature off. **Check the binary before spending GPU time:**
  `grep -qa -- "<key>" <binary>`.
* **Do NOT verify with `strings <bin> | grep -q`.** Under `set -o pipefail` that gives a FALSE
  "absent": `grep -q` exits on first match, `strings` dies of SIGPIPE (141), pipefail promotes it.
  It is a race — it passes on the front end and fails on compute nodes. Reproduced in job 2495353.
  Use `grep -qa` directly on the binary. See `/beegfs/u/bbg6470/wp0_repro/README_wp8build_2495349.md`.

## 2. **Physics at higher densities — the known ceiling** (do this first)

The EOS and opacity tables do **not** cover the same density range, and the mismatch is silent.

| table | ρ range | T range | file |
|---|---|---|---|
| EOS (hires v2) | 1e-20 … **1.00e+00** g/cm³ | 8 … 3.02e5 K | `src/eos/eos_table_hires_v2.bin` |
| Opacity (v2) | 1e-20 … **1.00e-02** g/cm³ | 3 … 1.00e5 K | `src/radiation/opacity_table_v2.bin` |

Re-derive with:
```bash
$PY -c "
import numpy as np
i=np.fromfile('src/radiation/opacity_table_v2.bin',dtype=np.int64)
f=np.fromfile('src/radiation/opacity_table_v2.bin',dtype=np.float64)
nr,nT=i[4],i[5]; lr0,dlr,lT0,dlT=f[6],f[7],f[8],f[9]
print('opacity rho %.2e..%.2e  T %.2e..%.2e'%(10**lr0,10**(lr0+(nr-1)*dlr),10**lT0,10**(lT0+(nT-1)*dlT)))"
```
(Header layout is `int64[magic,ver,flags,ng,nr,nT]` then `float64[lr0,dlr,lT0,dlT,0,0,0]` — see
`gen_opacity_table.py:199`. Note `f[7]` is the **spacing**, not the max; misreading it as the max
gives a wrong 2 g/cm³ answer.)

**The opacity ceiling is 1e-2 g/cm³ = 1e11 × `rhocrit`, and the second core forms right there.**

**And it is clamped silently.** `radiation_opacity.hpp`, `Real bilin(...)`: both the index and the
interpolation weight are clamped (`if (i > nr_-2) i = nr_-2; ti = ... > 1 ? 1 : ti`). Past the edge
you get the edge opacity, no warning, no error.

**So before any deep run:**
1. Decide whether the run will exceed 1e-2 g/cm³. `rhocrit = 1e-13` (`fhc_rootladder.in:257`), so
   this is ~1e11 × rhocrit.
2. If yes, either regenerate the opacity table to match the EOS —
   `$PY src/radiation/gen_opacity_table.py --rho_max 1e0 ...` (defaults are `--rho_min 1e-20
   --rho_max 1e-2 --nr 60 --nT 120`) — or add an explicit out-of-range diagnostic so the clamp
   stops being silent. The EOS side already covers 1 g/cm³, so only the opacity needs extending.
3. Whatever you do, **record it**: `src/eos/TABLE_PROVENANCE.md` is the existing record of table
   provenance and hashes, and the hires tables are gitignored deliberately (regenerable, too big).

### GPU allocation — a live bug you must work around

`wrap_mod.sh` (copied into every run dir) does:
```bash
NGPU=$(nvidia-smi -L | wc -l); export CUDA_VISIBLE_DEVICES=$(( local_rank % NGPU ))
```
It derives the device from what is **visible** and overwrites the correct list SLURM exported.
`nvidia-smi` is not reliably restricted to the allocation: on g004 it listed **6** devices for a
5-GPU job, so rank 2 landed on a card holding 35 975 MiB of someone else's memory → OOM
(job 2495385). The other face is `cudaErrorInitializationError` on a card you were never granted
(job 2495384).

**Fix already written and tracked: `runs/wp8_dissplit/wrap_slurm.sh`** — indexes into
`CUDA_VISIBLE_DEVICES` as SLURM set it. It is wired into the WP-8 scripts only.
**Rolling it across the ~100 production run dirs is a user decision — not done.**

Also: `squeue -p gpu` shows *no* jobs while nodes report GPUs allocated (other users are invisible
to you), so contention can only be **measured at runtime**. `submit_rung.sh` has a GPU preflight
worth copying — it refuses in seconds instead of dying minutes in. And note **a contended job
still reports SLURM `COMPLETED 0:0`**, because the batch script succeeds while `mpirun` dies:

### Unit conventions — the standing landmine

* Code units are shared with Athena++ (`rho0=5.467e-19`, `v0=1.9e4`, `l0=2.81e16`, `t0=1.48e12`,
  `four_pi_G=1`).
* **AthenaPK B is Heaviside-Lorentz** (`v_A=B/√ρ`, `P_mag=B²/2`); Athena++ is Gaussian
  (`v_A=B/√(4πρ)`). The *code-unit B number is the same*; only the `v_A` formula differs.
* `units.json`'s `code_bfield_cgs` is the **HL** unit — converting to Gauss needs another √(4π)
  (a 3.545× error if taken at face value).
* `.hst` files carry only **6 significant figures**. Do not set reconstruction tolerances tighter
  than ~1e-5 against them; use `.phdf` for small effects.

### phdf layout

`prim` is `[block, component, k, j, i]`, components `0=density, 1-3=velocity, 4=pressure, 5-7=B,
8=psi, 9+=scalars`. Align raw reads against `Info/ComponentNames` — that attribute concatenates
**all** datasets, `grav.phi` first. Slab reads are ~30× faster than component slices.

## 7. Working rules that were learned the hard way

These are in `CLAUDE.md` and `/beegfs/u/bbg6470/OPUS_PROMPT.md`; these five earned their place
during this campaign:

1. **Evidence before assertion.** Every number stated must come from something read this session,
   or be labelled recalled/estimated. When a note and the artifact disagree, the artifact wins —
   and the disagreement is itself a finding.
2. **Falsify before reporting.** Construct the observation that would hold if you were *wrong* and
   check it. This campaign: a "converged" `dissO` (3 rungs) was destroyed by a 4th; a gate said
   "keys ABSENT" from a binary that contained all of them; a checker read the `.hst` print format
   as a physics defect; and an epoch mismatch made a healthy rung look 200× wrong.
3. **Match on the physical variable, not the convenient one.** WP-8 rungs are compared at fixed
   **density**, never fixed time — they reach ρ=1e-12 at genuinely different epochs (nj4 t=1.0937,
   nj32 t=1.1267). Comparing at fixed time compares different physical states.
4. **"Implemented and gated" ≠ "in effect".** Several fixes sat behind flags no deck had ever set.
   Check the adoption count (`grep -r` the whole `runs/` tree and *count*) before believing a
   feature is live.
5. **Gate before you spend.** A 0.8 GPU-h probe caught the binary/diagnostic mismatch that would
   have wasted ~11 GPU-h, twice. Stage expensive work behind a cheap discriminating test.
